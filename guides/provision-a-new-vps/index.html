    Provision a new VPS¶

    This guide takes a freshly created cloud server, the kind Hetzner Cloud or DigitalOcean hands you with only root and your SSH key, to a hardened web server in three sadame apply runs: an administrator account, a security baseline (SSH on port 2222 with keys only, a firewall, fail2ban, automatic updates) and nginx serving a site. Each step is one of the examples, used as it is, and the output below comes from running exactly these commands against a fresh Debian 12 server.

    What you need¶

    • sadame on your machine (see Install) and a checkout of the repository for the examples, or copies of examples/06-app-deploy-user, examples/07-hardening-baseline and examples/02-nginx-static-site;
    • an SSH key pair; the commands below use ~/.ssh/id_ed25519.pub;
    • a new server running Debian 12 or Ubuntu 24.04, reachable as root with that key.

    1. Create the server¶

    Create it with your public key, in the web console or with the provider's CLI. With Hetzner Cloud's hcloud, after hcloud ssh-key create --name me --public-key-from-file ~/.ssh/id_ed25519.pub:

    hcloud server create --name vps1 --type cx22 --image debian-12 --ssh-key me   # types: hcloud server-type list

    With DigitalOcean's doctl, using the fingerprint from doctl compute ssh-key list:

    doctl compute droplet create vps1 --image debian-12-x64 --size s-1vcpu-1gb --region fra1 --ssh-keys FINGERPRINT

    Note the server's IP address; the commands below write vps1.example.com in its place. Connect once with ssh root@ADDRESS to check the key works and to accept the host key.

    5. Check the result¶

    drift on the baseline exits 0: everything is as the recipe says. Root can no longer log in, and port 22 no longer answers:

    $ sadame drift examples/07-hardening-baseline -h deploy@vps1.example.com:2222 --sudo --var open_ports=80,443
[vps1.example.com] sadame 0.3.0 drift on vps1.example.com (Debian GNU/Linux 12 (bookworm))
[vps1.example.com]
[vps1.example.com] No drift: 16 resources match the recipe.

Hosts
  vps1.example.com  ok

drift on 1 host: 1 ok. Finished in 0.31s.

$ echo $?
0

$ ssh -p 2222 root@vps1.example.com true
root@vps1.example.com: Permission denied (publickey).

$ ssh -p 22 deploy@vps1.example.com true
ssh: connect to host vps1.example.com port 22: Connection timed out

    Keep it in an inventory¶

    Typing -h deploy@...:2222 --sudo gets old. Put the server in a hosts.rb, as examples/07-hardening-baseline/hosts-after.rb does, and use -g:

    examples/07-hardening-baseline/hosts-after.rb
    # After the first apply: SSH listens on vars[:ssh_port] (2222) only.
group :new do
  host "vps1.example.com", user: "admin", sudo: true, port: 2222
end

    Then Drift in CI checks the server every morning.

    Common mistakes¶

    • Running the baseline before the administrator account. The baseline turns off root login; without another user with a key and sudo, you are locked out.
    • Forgetting open_ports. The firewall only lets SSH in. A web server needs --var open_ports=80,443 (or open_ports: [80, 443] in vars.rb).
    • Connecting to port 22 after the baseline. Use HOST:2222, port: 2222 in hosts.rb, or Port 2222 in ~/.ssh/config.
    • The provider's own firewall. Hetzner and DigitalOcean also have firewalls outside the server; open ports 2222, 80 and 443 there too if you use them.
